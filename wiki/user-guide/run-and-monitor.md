# 运行与监控执行

> 本文介绍如何运行工作流并实时观察执行过程。架构背景见 [系统总览](../architecture/overview.md)。

## 1. 手动运行

在画布编辑器或工作流相关页面点击**运行（Run）**，即可立即执行当前工作流。

- 运行前请确保已**保存**最新编排。
- 若节点参数有必填项未填，通常会被拦截并提示，需先补全。
- 部分工作流可能需要你提供一次性输入（如本次执行的初始数据），按页面提示填写即可 待确认。

## 2. 实时观察节点状态

执行开始后，系统通过 WebSocket 把进度实时推送到页面，你**无需刷新**就能看到：

- 当前正在执行的节点会**高亮**（例如变为进行中颜色）。
- 已成功完成的节点、出错的节点会有不同状态标识。
- 整体进度（进行中 / 成功 / 失败 / 部分完成）会在执行视图中显示。

这让你可以像"看着流水线条"一样，确认流程有没有按预期走。

## 3. 查看每个节点的输出

点击画布上（或执行详情里）的某个节点，可以查看该节点本次执行的**输出内容**，例如：

- HTTP 节点返回的响应数据；
- 判断节点的分支结果（走了"真"还是"假"）；
- 某个节点加工后的数据，供下游使用。

若某节点执行失败，这里通常会展示错误原因，方便你回到画布修正参数后重新运行。

## 4. 执行历史与记录

每次运行都会留下一条**执行记录**，可在执行历史 / 监控页面查看过往运行：

- 运行时间、触发方式（手动 / 定时 / Webhook / 轮询）、最终结果；
- 逐节点的状态与输出，便于排查问题或复盘。

> 凭据等敏感信息不会出现在输出或日志中，详见 [凭据管理](credentials.md)。

## 5. 其他触发方式

除了手动点"运行"，工作流也可以由以下方式自动启动（配置方法见 [触发器配置](triggers.md)）：

- **定时（Schedule）**：按 cron 计划周期性运行；
- **Webhook**：收到外部系统推送的请求时运行；
- **轮询（Poll）**：按间隔不断检查某条件，满足时运行。
