# 凭据管理（UI 视角）

> 本文介绍如何在不暴露密钥明文的前提下，让工作流节点安全地使用账号、令牌等敏感信息。架构与加密细节见 [系统总览](../architecture/overview.md)。

## 1. 为什么需要凭据？

很多节点（如 HTTP 请求、调用第三方 API、连接数据库）需要**账号密码、API Key 或 Token** 才能工作。

如果把这些秘密直接填进节点参数里，会带来两个问题：

- 明文暴露在画布和配置中，容易被误看、误复制；
- 输出、日志中可能意外泄露。

凭据管理就是为了解决这个问题：**你在凭据管理里集中创建秘密，节点只按"引用"使用它，明文不进画布、不进日志。**

## 2. 创建一条凭据

在界面的凭据入口（如凭据面板 / 菜单）中创建：

1. 点击**新建凭据**。
2. 填写凭据的**名称**（便于在节点里识别，例如"GitHub Token"）。
3. 选择凭据**类型**。系统内置以下 8 种类型（由 `CredentialTypeRegistry` 注册，页面下拉即来源于此）：`apiKey`（API Key）、`database`（数据库连接）、`basicAuth`（用户名密码）、`oauth2`、`smtp`、`s3`（兼容 S3 对象存储）、`redis`、`mongo`（MongoDB）。节点参数若声明了凭据类型约束，下拉会按约束过滤。
4. 填入对应的密钥 / 令牌内容。
5. 保存。

保存后，系统会将该秘密**加密存储**（后端采用 AES-GCM 静态加密），页面上不会再显示明文，日志里也绝不会出现明文。

## 3. 在节点里引用凭据

配置节点参数时，涉及认证的字段通常是**下拉选择**而非文本框：

- 选择你之前创建的凭据名称即可；
- 节点执行时，系统自动解密并注入对应秘密，你无需、也不能看到明文。

这意味着：换令牌时，只需在凭据管理里更新这一条，所有引用它的节点自动生效，不用逐个改节点。

> 通过 AI Agent（MCP）编排时，凭据也是用**凭据 ID** 引用的，详见 [通过 AI Agent 编排](ai-agent.md)。

## 4. 维护建议

- 给凭据起**清晰、可辨识**的名字，避免日后分不清用途。
- 离职或不再使用的凭据及时**停用 / 删除**，降低泄露风险。
- 凭据一旦创建，明文通常不可回看；若遗忘只能重新生成并覆盖更新。

## 5. 安全说明

- 凭据明文**不落日志、不返回前端**。
- 后端以加密形式持久化，运行时才解密注入节点。
- 节点插件在隔离的加载上下文中执行，进一步约束秘密的可见范围。
